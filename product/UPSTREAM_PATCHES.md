# Реестр изменений в коде upstream

Любой файл, который есть в upstream (Open.IdentityServer), по умолчанию менять нельзя.
Если без правки не обойтись, файл добавляется в эту таблицу **в том же PR**, где он меняется.
Иначе проверка `upstream-boundary` не пропустит PR.

Правила:

- Сначала убедиться, что задачу нельзя решить расширением (см. [README.md](README.md#как-расширять-не-меняя-upstream)).
- Правку вносит человек. ИИ-агентам изменения upstream-файлов запрещены настройками `.claude/settings.json`.
- Одна строка — один файл. Путь от корня репозитория, в обратных кавычках, в первой колонке.
- Изменение внутри файла минимальное и помечено комментарием `FORK-PATCH: <краткая причина>`.
  Для форматов без комментариев (`.json`, `.sln`) причина пишется только здесь.
  Пометка заодно выполняет требование Apache 2.0 об уведомлении об изменённых файлах.
- Если патч полезен всем — отправляем его в upstream и указываем ссылку на PR.
- Когда upstream принял исправление или патч больше не нужен — строку удаляем при ближайшей синхронизации.
  Проверка `upstream-boundary` предупреждает о строках, файл которых совпадает с upstream.
