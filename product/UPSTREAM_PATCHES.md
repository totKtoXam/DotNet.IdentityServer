# Реестр изменений в коде upstream

Любой файл, который есть в базовом релизе upstream (Open.IdentityServer), по умолчанию менять нельзя.
Если без правки не обойтись, файл добавляется в таблицу ниже **в том же PR**, где он меняется.
Иначе проверка `upstream-boundary` не пропустит PR.

Правила:

- Сначала убедиться, что задачу нельзя решить расширением (см. [README.md](README.md#как-расширять-не-меняя-upstream)).
- Правку и строку реестра вносит человек. ИИ-агентам правка upstream-файлов и этого реестра запрещена
  (`.claude/settings.json`).
- Одна строка таблицы — один файл. Путь от корня репозитория, в обратных кавычках, в первой колонке.
  Проверка читает только эту таблицу; строки вне неё считаются ошибкой.
- Изменение внутри файла минимальное и помечено комментарием `FORK-PATCH: <краткая причина>`.
  Проверка требует метку во всех форматах с комментариями (`.cs`, `.csproj`, `.props`, `.md`, `.yml`, `.sh`, ...);
  для форматов без комментариев (`.json`, `.sln`, бинарные) причина пишется только здесь.
- Удалять upstream-файлы нельзя даже через реестр: при следующей синхронизации это конфликт.
- Если патч полезен всем — отправляем его в upstream и указываем ссылку на PR.
- Когда upstream принял исправление или патч больше не нужен — строку удаляем при ближайшей синхронизации.
  Проверка предупреждает о строках, файл которых совпадает с upstream.
